# WMS 仓储与物流协同平台产品需求文档

版本：1.0｜日期：2026 年 10 月 29 日｜用途：产品设计、Cursor 开发、作品集演示

## 1 产品定位与目标

构建支持中文、英文、西班牙语的多仓、多货主管理平台，以 WMS 仓内执行为核心，连接 ERP、OMS、承运商与财务系统，扩展轻量运输调度、循环包装资产和费用对账。主线是业务单据来源可追踪、实物流转可执行、库存数量可解释、费用可复核。

本文是拟议产品设计，不代表已上线系统或个人既往项目成果。默认面向美国电商及第三方仓储场景，NJ、CA、TX 为演示仓库；这些是可调整的产品假设。

### 1.1 业务目标

- 仓库经理能够查看收货、上架、拣货、发货和异常任务，并定位阻塞原因。
- 操作员能使用熟悉的语言，在桌面端或移动扫码页面完成工作。
- 产品与技术人员能从上游单据追溯至库存流水、运输任务、费用和对账差异。
- 财务人员能核对承运商账单、仓储服务账单、仓库租金和车队费用。
- 资产管理员能追踪循环箱、托盘等可回收包装的所在地、持有人和归还义务。

### 1.2 系统边界

| 领域 | 本平台负责 | 外部系统负责 |
|---|---|---|
| ERP | 执行采购入库、调拨及退货指令并回传结果 | 采购合同、供应商采购付款、财务总账 |
| OMS | 接收履约指令、分配可履约库存并回传发货 | 销售订单、客户支付、营销与渠道订单 |
| 仓储 | 收发存、库位、任务、盘点、批次、库存追踪 | 自动化设备控制可后续连接 WCS |
| 运输 | 轻量车队档案、任务调度、装车、签收、费用关联 | 完整 TMS 路网优化、实时车联网和司机薪资 |
| 财务 | 费用计提、账单匹配、差异、审批和导出 | 会计凭证过账、银行支付、税务申报 |

## 3 用户角色与权限

权限模型：角色 × 动作 × 仓库 × 货主。前端隐藏按钮不等于权限控制；生产接口也必须验证。

| 角色 | 主要权限 |
|---|---|
| 系统管理员 | 配置用户、角色、语言、集成、主数据 |
| 仓库经理 | 本仓任务管理、库存审批、异常处理、经营看板 |
| 收货员 | 扫码收货、差异登记、提交质检，不可审批本人库存调整 |
| 上架/拣货员 | 查看并执行分配给本人的任务、登记异常 |
| 复核发货员 | 复核包装、装车、确认发货 |
| 调度员 | 分配司机车辆、维护运输任务、处理运输异常 |
| 司机 | 查看本人任务、更新节点、提交签收及循环箱交接 |
| 资产管理员 | 循环箱登记、借还、维修和报损申请 |
| 财务 | 费率合同、账单、对账、差异审批和财务导出 |
| 货主只读用户 | 查看本货主库存、订单和账单 |

高风险动作包括库存调整、强制释放、费率修改、差异核销、资产报损；要求原因、权限和审计记录。原始业务记录不可直接物理删除。

## 4 信息架构与页面规范

导航：工作台 / 入库管理 / 出库管理 / 库存管理 / 库位管理 / 智能分仓 / 运输与车队 / 循环箱与资产 / 费用与对账 / 报表 / 集成中心 / 系统设置。

单据列表统一支持搜索、仓库、货主、状态、来源、日期筛选，分页、列设置、导出、空状态和加载失败重试。详情页统一包含摘要、明细、关联单据、操作记录和附件。状态、金额、数量必须能追溯到明细；看板不能独立维护一份假数据。

桌面端用于管理与分析；移动端用于扫码、任务确认和司机签收。颜色辅助表达状态，同时保留文字和图标。批量操作前展示可处理数量与失败原因。

## 5 三语与地区设置

### 5.1 功能要求

- 支持 zh-CN、en-US、es-US，登录前后均可切换；优先级为用户偏好、浏览器支持语言、默认英文。
- 切换语言保留当前页面、筛选、选择和未提交表单，偏好持久化。
- 翻译覆盖导航、字段、枚举、校验、弹窗、通知、空状态、报表标题、打印模板和无障碍标签。
- 状态和业务逻辑使用稳定代码，不把翻译后的字符串作为判断依据。
- SKU、单据编号、人员姓名、用户备注及上游原文保留原始内容；商品可选维护三语名称，缺失时显示默认商品名称。
- 语言、时区、币种、单位独立配置。美国仓库分别使用 IANA 时区；时间存 UTC，展示明确当地时区。
- 币种显式显示 USD 等代码；货币使用最小单位整数或精确十进制。语言切换不换汇。
- 重量与尺寸保留原始单位和标准换算值；费率计算必须明确 lb/kg、in/cm。
- 西班牙语使用面向美国仓储作业的中性表达，布局允许文字变长；复数和日期由国际化库处理。
- 开发环境缺失翻译应可发现；发布前核心流程不得出现翻译键或混杂语言。

## 6 基础资料与单据来源

### 6.1 主数据

- 组织：租户、货主、仓库、供应商、客户、承运商、车队、结算主体。
- 商品：SKU、三语名称、条码、包装层级、单位换算、重量尺寸、序列号/批次/效期标记、存储要求、默认分配策略。
- 仓库：地址、时区、营业时间、出库截单时间、联系人。
- 库位：仓库、分区、巷道、货架、层、位置、唯一库位码、类型、容量、允许商品、启停状态。
- 商业配置：费率合同、服务项目、账期、币种、生效日期和审批版本。

### 6.2 单据来源通用字段

入库和出库列表均展示：创建方式、来源系统、上游单据类型、上游单号、创建人、创建时间。详情增加同步时间、外部版本号、最后同步结果、关联事件和操作日志。

创建方式枚举 SYSTEM_SYNC / MANUAL / FILE_IMPORT；来源系统如 ERP / OMS / WMS。创建方式与系统分别记录。手工单来源为 WMS；文件导入记录原始系统及导入人；不得将导入人误显示为上游业务创建人。

- 同步单上游业务字段默认只读，实收、库位、拣货结果由 WMS 维护。
- 手工单必须选择业务类型、原因、货主、仓库，支持草稿和提交；是否审批由类型配置。
- 幂等键包含租户、来源系统、上游单据类型和单号；事件另有唯一 event_id。
- 同步状态独立于作业状态；“同步成功”不能表示“已经收货”。
- 未开始作业时可受控更新；已开始后，上游改量或取消形成变更请求及异常，禁止覆盖已发生的库存流水。
- 已完成单据只允许关联退货、冲销或调整，不允许直接改写历史。

## 7 入库管理

类型：采购入库、调拨入库、客户退货、其他入库。页面：入库单列表/详情、收货工作台、质检队列、上架任务、差异处理。

### 7.1 标准流程

草稿 → 待收货 → 收货中 → 待上架 → 上架中 → 已完成。允许部分收货、部分上架；另设已取消和已关闭。完成条件为实收数量均有明确去向，未收数量已等待后续或批准短收关闭。质检作为独立任务状态，不强迫整单只有一个简单状态。

1. 接收 ASN 或手工创建，包含供应商、预计到货、SKU、预期数量、批次/效期、附件。
2. 扫入库单、商品或箱码，登记实收、合格、不合格、缺少和超收数量。
3. 超收按容差和权限处理；少收形成差异，不能自动补足库存。
4. 收货确认后合格品进入收货暂存区，待检与不良品进入隔离区；此时计入仓内实物但不可分配。
5. 推荐上架库位，校验货主、商品存储要求、容量、冻结和启停状态，允许有权限人员改位并记录原因。
6. 扫来源容器、目标库位和商品确认上架，库存从暂存区转入目标库位；只有满足释放条件的库存进入可用量。
7. 回传实收、差异、上架完成结果；回传失败不回滚真实收货，进入重试队列。

验收：预计 100 件、实收 98 件时只增加 98 件实物；短收 2 件可追踪；上架前不可被订单预占；重试收货不会再次加库存。

## 8 出库管理与智能分仓

类型：销售出库、调拨出库、供应商退货、其他出库。页面：出库单、分配工作台、波次、拣货、复核包装、发运交接。

### 8.1 标准流程

草稿 → 待分配 → 已分配 → 拣货中 → 待复核 → 待发货 → 部分发货/已发货 → 已关闭；取消独立处理。订单、履约子单、拣货任务、包裹、运输任务分别建模，避免一个订单状态替代全部执行状态。

1. 校验货主、地址、SKU、数量和截止要求。
2. 推荐仓库：先过滤库存不足、停用、不可配送及不满足货主权限的候选，再比较时效和成本。
3. 演示评分使用可配置权重及明确归一化方式，展示候选值、权重、淘汰原因和推荐原因。费用无数据时显示估算依据，不宣称生产 AI 优化。
4. 优先单仓履约；不足时根据订单是否允许拆分决定拆仓、部分分配或等待补货。人工覆盖记录原因。
5. 按 FIFO 或 FEFO 预占具体库存；FEFO 排除已过期及不满足剩余保质期要求的库存。
6. 生成含来源库位、SKU、批次、数量、目的容器的拣货任务；P1 支持按仓、货主、渠道、截单时间组波次。
7. 拣货后货物移至包装或发运暂存位，实物仍在仓内，订单占用仍保留；复核数量、重量、包裹及标签。
8. 承运商交接确认后扣减仓内实物和对应预占，生成出库流水、包裹追踪号及回传事件。

### 8.2 异常与取消

- 短拣：记录位置、期望和实际数量，冻结疑似问题库存，触发复盘/盘点；经验证后释放原预占并重新分配，不能凭空增加库存。
- 取消：未拣货可释放；已拣货生成退拣返架任务；已发货使用退货流程。
- 分批发货：每一批只扣减本次交接量，剩余预占继续保留；商品行有累计已发与未发数量。
- 补货：从存储区向拣货区生成内部移库任务，不能直接更改库存总量。

## 9 库存与库位管理

### 9.1 库存口径

库存最小管理维度为租户、货主、仓库、库位、SKU、批次、品质状态；序列号管理商品额外关联 serial_id。库内容器通过 LPN 标识。

- On Hand：仓内实物总量，包含收货暂存、合格、隔离、不良和已拣待发货等互斥状态。
- Allocatable On Hand：其中处于允许分配的库位、品质及效期状态的实物。
- Reserved：对可分配实物及已拣待发实物的有效订单占用，分别记录位置和状态。
- Available：未拣货的可分配实物减去对该部分的预占；已拣量不再计入可分配基数，避免再次扣减。
- In Transit：已出源仓、未收目的仓，独立记录，不计入任一仓 On Hand。

演示必须展示库存口径说明。不得简单用所有 On Hand 减所有 Reserved 作为可用库存。库存状态转换必须互斥，冻结与预占重叠时要记录占用并触发重新分配，避免双扣。

### 9.2 库位规则

类型：收货暂存、待检、存储、拣货、包装、发货暂存、不良品、退货。容量可按件、托盘位、体积或重量配置，必须标明生效的容量口径；商品体积缺失时不得伪造精确容量校验。停用禁止新任务，现有库存及未结任务必须先处理或批准迁出。

移库使用“申请 → 执行 → 完成”流程，扫描两端并原子性变更；总仓库存不变。跨仓调拨必须关联出库、在途和入库，不能作为一次库位移动。

### 9.3 盘点与流水

- 支持库位/SKU/ABC 周期盘点和全盘；可盲盘，记录盘点范围的冻结或库存快照与期间移动。
- 差异进入复盘和审批，批准后生成调整流水；禁止直接编辑余额。
- 流水包含前后数量、变动量、来源/目标、单据、任务、操作者、原因、UTC 时间、关联事务号。
- 库存扣减和预占需事务与并发控制；负库存默认禁止。

## 10 运输与车队管理

本模块是轻量运输协同，支持自有车队和外包承运商。司机界面以任务和交接为主。

### 10.1 档案

- 车辆：车辆编号、车牌、类型、容量、所属主体、状态、保险/检查到期、里程、维保记录。
- 司机：姓名、联系方式、可用时间、服务区域、证照到期、所属车队。敏感证件限制访问。
- 承运商：服务范围、合同、计费方式、联系人、结算周期和履约指标。

### 10.2 运输任务

任务关联一个或多个包裹、出库批次或调拨单，包含起终点、停靠点、预约时间、载货重量体积、司机车辆、循环箱交接量、预计与实际节点。

状态：待调度 → 已派车 → 待装车 → 运输中 → 已送达 → 已关闭；另有取消、失败和部分签收。运输送达不改变源仓已经发货的事实。

- 派车时校验车辆与司机时间冲突、容量、可用状态及配置的到期阻断规则。
- 装车扫描校验包裹与任务一致，生成交接清单。
- 支持签收人、时间、数量、照片或签字附件；短少、拒收、损坏生成异常。
- 司机未收到货不得提交相应资产归还；交接需要双方确认或按授权进行异常确认。
- 演示使用模拟轨迹或节点时间线，明确标注模拟；不承诺实时 GPS。

### 10.3 车队成本

记录燃油、通行费、停车费、维修、租车、承运运费等费用及凭证，可关联车、趟次或期间。司机薪资计算留给外部系统。公共费用分摊须指定规则和版本，不应同时完整计入多个趟次。

## 11 循环箱与可回收资产管理

资产包含循环箱、周转筐、托盘及保温箱。必须区分资产所有权、实际所在地、当前持有人和待归还义务；库内 LPN 仅表示物流容器标识，不自动等于企业自有循环资产。

### 11.1 数据和操作

资产类型记录规格、材质、容量、是否逐件序列化、押金规则、标准使用周期；资产实例记录唯一码/二维码、所有方、保管方、地点、状态、购入日期及关联交接单。低值非序列化资产允许按类型和保管方数量管理，两种模式不可混算。

流程：登记 → 可用 → 发放/在用 → 待归还 → 已回收 → 待清洗/待检 → 可用；分支包括维修、遗失和报废。流转状态、清洁状态和物理位置分开维护。

- 发放：绑定运输或出库任务、接收方、交接数量、预计归还日、交接证据。
- 回收：扫码/计数、确认归还方、差异、损坏和收货位置，支持部分归还。
- 在途：记录发出、签收，不在两个地点同时计可用数量。
- 维修/清洗：处理后检查释放；遗失和报废需原因及审批，归还义务通过核销单结清。
- 押金：单独记录应收、已收、可退、已退和扣罚；本平台记录与导出，不执行真实收付款。
- 盘点：对照保管方账面与实际，形成资产差异单。

报表：资产余额、在外数量、逾期数量、周转时长、丢失率、损坏率和客户待还明细。周转时长以发放至实际回收为准，未归还资产单独计在外天数。

## 12 费用计费与对账

### 12.1 四类费用和业务边界

| 类别 | 业务证据 | 费率依据 | 核对对象 |
|---|---|---|---|
| 物流运费 | 包裹、重量尺寸、区域、发货/签收记录 | 承运商合同、分区、计费重、附加费 | 承运商账单/发票 |
| 对货主仓储收费 | 收货、上架、存储快照、拣货、包装、退货 | 货主服务合同 | 本平台应收账单及货主反馈 |
| 仓库租金与物业 | 租约、计租面积、账期、费用通知 | 固定租金、面积单价、约定递增、物业项目 | 房东/物业应付账单 |
| 车队费用 | 趟次、车辆、里程、燃油及通行凭证 | 运输合同或内部成本规则 | 外包车队账单及内部费用记录 |

仓库租金是企业占用场地的成本；对货主收取的仓储费是服务收入，必须分账。自有车队成本归集与外包运费应付也应区分。没有外部账单的成本使用费用台账，不强行生成“对账成功”。

### 12.2 计费引擎

费率记录客户/供应商、合同版本、服务项目、适用仓库、日期、币种、单位、阶梯、最低收费及舍入规则。按作业发生日选择费率版本，保留计算输入和结果快照。

- 运费：计费重 = max(实重, 按合同除数计算的体积重)，再按合同进位、分区费率和附加费计算。除数与进位不可硬编码为统一行业值。
- 存储：可选托盘日、库位日、体积日等；按仓库当地约定截点生成快照，明确首尾日和不足一日规则。
- 作业：按单、件、箱、行或工时计费，避免同一事件重复计费。
- 租金：按租约期间计提，首尾月是否按日折算由合同配置；物业、税费分摊单列，不预设所有租约相同。
- 费用使用明确的含税/未税字段，不自行推断税务处理；多币种对账分别汇总，换汇需记录来源、日期与汇率。

### 12.3 对账流程

合同/费率 → 作业证据 → 预计费用 → 导入对方账单 → 自动匹配 → 差异处理 → 审批 → 确认结算 → 财务导出。

对象：账单头、账单行、费用事件、匹配关系、差异单、调整单、结算单。匹配关系支持一对多和多对一；每项证据的已匹配数量和金额不能超出可匹配余额。

导入支持 CSV 模板、列映射、预览和行级校验；记录文件标识、供应商、账单号、版本和原始行号。重复导入同一文件或账单不得重复入账，修订版走版本变更。

匹配顺序：结算主体与币种 → 追踪号/运输任务/合同期间等业务键 → 服务项目 → 数量及金额。模糊匹配只给建议，不自动确认。缺单、重复收费、重量差、费率差、附加费差、账期差和币种差分别展示。

差异处理动作：接受对方金额、要求更正、补录合法费用、内部更正、部分确认、争议挂起；必须记录理由、附件、责任人和审批。容差按币种和项目配置，同时保留绝对差与比例差。批准容差不等于静默改写原始费用。

状态：草稿 → 已导入 → 对账中 → 待差异处理 → 待审批 → 已确认 → 已导出；付款状态单独记录为未支付/部分支付/已支付，仅由财务回传或授权登记，不把导出当作付款。

### 12.4 对账示例

承运商账单三行：运单 A 预计 USD 12.00、账单 USD 12.00，自动匹配；运单 B 预计 USD 18.00、账单 USD 21.00，形成 USD 3.00 附加费争议；运单 C 无本平台发货证据，进入未匹配。只有完成争议处理并审批的行进入已确认结算。

租金示例：合同月租 USD 8,000，房东账单 USD 8,300，USD 300 必须作为独立物业项目并提供依据；不得把差额直接覆盖成新月租。

## 13 集成中心

连接器列表展示来源、方向、最近成功时间、待处理量、失败量及状态。事件详情记录原始事件引用、业务单号、幂等键、重试次数、错误、关联 WMS 单号和响应摘要；敏感数据脱敏。

入站事件：inbound.created、inbound.changed、outbound.created、outbound.cancel_requested、master_data.updated。

出站事件：receipt.confirmed、putaway.completed、shipment.confirmed、inventory.adjusted、transfer.received、reconciliation.confirmed。

- 接收事件、校验、落库、执行业务和回执需有可追踪结果；处理失败可重试或进入死信队列。
- 重试使用原事件标识，不能制造新单；版本落后和乱序事件应拒绝或暂存，不覆盖新版本。
- 真实集成通过接口契约约定所有权和失败恢复；演示用“模拟 ERP 同步”“模拟 OMS 同步”和失败重试按钮清晰表达。
- WMS 是库内实物和执行结果来源；ERP/OMS 是各自业务指令来源。库存差异通过校准流程处理，不相互无条件覆盖。

## 16 非功能要求

演示版：模拟数据本地持久化，刷新后保留；提供一键恢复种子数据，提示会清除演示更改。角色切换只作演示，明确标识。无需真实支付、地图或外部 API 密钥。

生产候选目标，需通过测试验证后承诺：常规列表在定义数据规模下 P95 小于 2 秒；关键库存命令 P95 小于 1 秒；大批量导入异步执行并返回进度。目标负载基线为 3 仓、10 万 SKU、每日 1 万出库单，后续按实际场景修订。

生产版要求真实鉴权、租户和货主隔离、服务端校验、加密传输、附件访问控制、审计、备份与恢复演练；明确 RPO/RTO 后再作可用性承诺。日志避免存放完整证件及敏感客户资料。导出防止跨货主泄露及电子表格公式注入。

扫码支持键盘输入及扫码枪回车；移动端无摄像头权限时仍可手输。断网操作不显示为服务端已完成；生产离线队列需显式冲突解决，P0 不承诺离线执行。

## 17 指标定义

| 指标 | 定义 |
|---|---|
| 收货至上架时长 | 同一收货批次确认至完成上架的时长，部分完成单列 |

## 19 Cursor 开发执行要求

请先阅读现有项目并复用技术栈和组件。将本 PRD 作为目标需求，先输出当前已实现、缺失、冲突和建议任务清单，再按以下顺序开发；不要一次生成大量互不联动的静态页面。

1. 建立共享数据模型、种子数据、国际化字典、导航和通用列表/详情布局。
2. 完成入库、收货、上架、库位和库存流水，验证 A01–A03。
3. 完成出库预占、拣货、复核、发货与异常，验证 A04、A06–A08、A15。
4. 增加可解释分仓与拆单；建立简化的运输任务和循环箱发还闭环。
5. 建立费用事件、费率快照、账单导入、三行匹配与差异审批。先完成运费，再复用框架扩展租金、仓储收费和车队费用。
6. 补齐三语、关联跳转、角色效果、持久化和重置；验证所有已纳入范围的验收项。
7. 完成视觉打磨及演示说明，列明仍属规划的功能、模拟集成和生产缺口。

实现约束：状态转换集中管理；界面由同一数据状态驱动；库存与费用计算放在独立领域函数；多条记录变更具备原子性语义。原型可先用本地存储模拟，但要集中持久化与迁移版本，禁止每个页面各写一套数据。生产版再替换真实数据库与服务端命令。

测试优先覆盖库存守恒、并发预占、幂等发货、部分收发、费用重复、账单差异及权限隔离。三语检查覆盖主要流程、弹窗、错误和移动页面。每阶段报告实际完成项及可复现操作，不将模拟能力表述为真实外部连接。

## 20 今天的交付门槛与后续决策

今天优先交付三条可操作主线：① 收货上架至发货；② 发货关联运输任务及循环箱发还；③ 发货证据至运费账单差异处理。三语架构从第一步建立，核心主线必须三语可用。租金、车队复杂成本、完整计费策略允许分阶段补齐；若时间不足，优先删减 P1 页面而不是破坏主线数据一致性。
